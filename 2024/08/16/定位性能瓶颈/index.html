定位性能瓶颈

发表于 2024-08-16 更新于 2024-09-10 Waline： 本文字数： 1.6k 阅读时长 ≈ 1 分钟

1. CPU 使用情况

CPU 是服务器处理任务的核心资源。高 CPU 使用率可能导致系统变慢，特别是在 CPU 密集型应用中。

使用 top 和 htop

  • top:

    • 概述：top 是一个实时显示系统资源使用情况的工具，默认按 CPU 使用率排序进程。

    • 关键指标

      ：

      • %CPU: 每个进程的 CPU 使用率。
      • load average: 系统的平均负载，表示 CPU 正在处理的任务数量。一般来说，load average 大于 CPU 核心数量可能表明 CPU 过载。
      • us（user space）: CPU 在用户空间花费的时间比例，表示执行应用程序代码的时间。
      • sy（system space）: CPU 在内核空间花费的时间比例，表示处理系统调用的时间。
      • id（idle）: 空闲时间比例，如果接近 0%，则表示 CPU 处于高负载状态。

  • htop:

    • 概述：htop 是 top 的增强版，具有更友好的用户界面，支持垂直和水平滚动查看进程。

    • 使用

      ：

      • htop 会以彩色条显示每个 CPU 核心的使用情况，便于查看负载是否均衡。
      • 支持按进程名称、CPU 使用率、内存使用率等进行排序。

2. 内存使用情况

内存是系统中的关键资源，过度使用会导致交换（swap）到磁盘，从而影响性能。

使用 top 和 htop

  • top 和 htop 中的内存监控：
    • Mem: 显示总内存、已用内存、空闲内存、缓冲区/缓存等。
    • VIRT（Virtual Memory）: 进程的虚拟内存使用量。
    • RES（Resident Memory）: 进程的实际物理内存使用量。
    • SWAP: 如果系统开始使用交换空间，表示内存压力较大，可能导致性能问题。
  • 查找内存泄漏：
    • 排查使用高内存的进程，并持续监控其内存增长情况。持续增长的内存使用可能表明内存泄漏。

3. IO 使用情况

IO 包括磁盘读写操作，IO 性能瓶颈通常出现在磁盘访问频繁或存储速度较慢时。

使用 iostat

  • 概述：iostat 是一个显示磁盘 IO 活动的工具，帮助分析系统的读写性能。

  • 命令

    ：

    • iostat -x 1: 每秒更新一次详细的 IO 统计信息。

  • 关键指标

    ：

    • tps（transactions per second）: 每秒 IO 传输的次数。
    • r/s 和 w/s（reads/writes per second）: 每秒读取和写入操作的次数。
    • await: IO 操作的平均等待时间（以毫秒为单位），这个值越高，说明磁盘可能成为瓶颈。
    • %util: 磁盘的利用率，接近 100% 表明磁盘处于高负载状态。

4. 网络使用情况

网络是分布式系统中连接各个实例的重要资源，网络瓶颈会导致高延迟和数据丢失。

使用 sar

  • 概述：sar 是一个综合性的系统性能监控工具，能够监控 CPU、内存、IO、网络等多种资源。

  • 命令

    ：

    • sar -n DEV 1: 每秒显示网络接口的使用情况。

  • 关键指标

    ：

    • rxpck/s, txpck/s: 每秒接收和发送的包数。
    • rxbyt/s, txbyt/s: 每秒接收和发送的字节数。
    • ifutil: 网络接口的利用率，接近 100% 表明网络带宽已经饱和。

使用 iftop

  • 概述：iftop 是一个实时显示网络带宽使用情况的工具，可以查看各个连接的带宽使用情况。

  • 关键指标

    ：

    • TX/RX: 显示发送和接收的流量。
    • TOTAL: 显示总流量，帮助识别占用带宽较多的进程。

5. 结合使用

在实际场景中，可能需要结合使用多种工具进行综合分析。例如：

  • **使用 top 或 htop**：初步识别 CPU 或内存使用异常的进程。
  • **使用 iostat**：查看是否存在磁盘 IO 瓶颈。
  • **使用 sar 和 iftop**：分析网络性能问题。
